# 开屏广告展示形式（单页式 vs 双页式）A/B 测试 PRD

---

## 1. 实验背景与假设

* **业务背景**：当前 App 热启动开屏广告采用传统的“单页式（Single-page Splash）”直接加载展示形态。
* **核心假设**：引入“双页式（Two-stage/Pre-splash Page）”展示形式（即第一页广告展示后，会跳转展示下一页广告，可以设置定时自动跳转，也可以手动点击后再跳转），对开屏广告的eCPM会有明显提升，但也会拉长用户进入产品的流程，从而需要测试在提高eCPM的同时看用户对此形式的开屏广告接受度为多少，是否对收入是正向提升，最终目的还是在**保证用户体验的前提下拉升开屏 eCPM 与 ARPDAU**。

---

## 2. 实验分组与流量分配

```text
               ┌──► 对照组 (Control - 50%): 单页式开屏 (直接请求并展示)
[全量用户分流] ┤
               └──► 实验组 (Treatment - 50%): 双页式开屏 (两段式广告展示)
```
| 分组 | 流量占比 | 逻辑说明 |
| :--- | :--- | :--- |
| **对照组 (Control Group)** | 50% | 热启动直接弹出开屏广告，加载失败则直接进入 App 主界面。 |
| **实验组 (Treatment Group)** | 50% | 先展示 3-5 秒第一页广告，再展示第二页广告，两页广告加载完成后进入 App 主界面，加载失败则直接进入 App 主界面。 |

---

## 3. 核心观测指标矩阵

### 主观测指标 (Primary Metrics)
* **开屏广告 eCPM**：评估 Bidding 和 Waterfall 的实际 eCPM 是否有所提升。
* **开屏广告展示率 (Show Rate)**：Show Rate = 实际展示数 / 广告填充数，验证加载缓冲对渲染成功率的拉动。
* **开屏广告收入及 ARPDAU**：评估开屏单广告位对综合收入的贡献增量。

### 护栏 / 反向指标 (Guardrail Metrics)
* **冷/热启动流失率与 D1 留存率**：监控双页过渡是否导致用户等待焦虑而直接跳出。
* **首屏主界面到达率**：确保广告跳过/关闭按钮响应灵敏，不破坏基础用户体验。

---

## 4. 决策与上线 / 熔断机制

* **全量（100% Launch）标准**：
  * 实验组开屏 ARPDAU **提升 $\ge 5\%$** 且统计显著（p < 0.05）；
  * 对照组与实验组在 **D1/D7 留存率上无显著差异**（波动 $\le \pm 0.5\%$）。
* **熔断（Rollback）机制**：
  * 若实验组因等待时间拉长导致 **D1 留存率下降超过 3%**，或**收益保持持平，甚至下降趋势**，立即停止分流并回滚至单页式方案。
